# Configuration

## Settings File

Settings are managed in `~/.keepmind/settings.json`. The file is auto-created with defaults on first run.

### Core Settings

| Setting                       | Default                         | Description                           |
|-------------------------------|---------------------------------|---------------------------------------|
| `KEEPMIND_MODEL`            | `claude-haiku-4-5-20251001`     | Claude model used to compress observations (when using the Claude provider) |
| `KEEPMIND_PROVIDER`         | `claude`                        | AI provider. `claude` is the supported path; `gemini` and `openrouter` still work but are unmaintained — see below |
| `KEEPMIND_CLAUDE_AUTH_METHOD` | `subscription`                | Claude provider auth mode: `subscription`, `api-key`, or `gateway` |
| `KEEPMIND_MODE`             | `code`                          | Active mode profile (e.g., `code--es`, `email-investigation`) |
| `KEEPMIND_CONTEXT_OBSERVATIONS` | `50`                        | Number of observations to inject      |
| `KEEPMIND_WORKER_PORT`      | `37700 + (uid % 100)`           | Worker service port (per-user default; override for fixed port) |
| `KEEPMIND_WORKER_HOST`      | `127.0.0.1`                     | Worker service host address           |
| `KEEPMIND_DATA_DIR`         | `~/.keepmind`                 | Data root — every other path (database, chroma, logs, settings.json, worker.pid) derives from this |
| `KEEPMIND_SKIP_TOOLS`       | `ListMcpResourcesTool,SlashCommand,Skill,TodoWrite,AskUserQuestion` | Comma-separated tools to exclude from observations |

### Alternate providers: maintenance status

`claude` is the provider keepmind is developed and measured against. `gemini`
and `openrouter` still function, but as of **3.4.0 they no longer receive the
observer work**, and the gap is not cosmetic:

| Capability                                             | `claude` | `gemini` / `openrouter` |
|--------------------------------------------------------|----------|--------------------------|
| Outbound secret redaction                               | yes      | **yes** — it lives in the shared prompt builder |
| Stateless compression (no growing conversation)         | yes      | no — full history per turn |
| Pre-model capture gate (`KEEPMIND_CAPTURE_PROFILE`)     | yes      | no — every tool use is compressed |
| Deterministic `files_read` / `files_modified`           | yes      | no — taken from the model |
| `KEEPMIND_OBS_FIELD_MAX_CHARS` budget                   | yes      | no — fixed 2000-char default |

In practice that means an alternate provider costs substantially more per
session for the same memory, because it pays for the two things the 3.4.0 work
removed: re-reading its own history every turn, and asking the model to judge
tool uses that can be judged for free.

Redaction is the one thing that is NOT weaker there — it is applied in
`src/sdk/prompts.ts`, which every provider goes through.

Use them if you need them; do not expect parity. Bug reports are welcome,
feature parity is not planned.

### Semantic Search

| Setting                  | Default                         | Description                           |
|--------------------------|---------------------------------|---------------------------------------|
| `KEEPMIND_EMBED_MODEL`   | `Xenova/multilingual-e5-small`  | Sentence embedding model. Must be 384-dimensional; anything else will not fit the vector schema. |
| `KEEPMIND_EMBED_DTYPE`   | `int8`                          | Quantization. `fp32` is larger and slower and measured no better on retrieval. |
| `KEEPMIND_EMBED_BATCH`   | `16`                            | Inference micro-batch. Lower it if embedding peaks too much memory. |
| `KEEPMIND_EMBED_IDLE_MS` | `300000`                        | Idle time before the model is unloaded to free memory. |

The default model is multilingual on purpose: memories are written in English
while questions are often asked in another language, and an English-only model
cannot bridge that — non-English queries silently degrade to keyword hits.

**Changing the model triggers a full rebuild.** Vectors from two different
models are not comparable, so the store records which embedder filled it and
re-embeds the entire corpus in the background at the next worker start when that
changes. The rebuild reads from SQLite, so it covers everything ever captured,
not just new memories. Keyword search stays available while it runs. Models with
a dimension other than 384 are not supported without a schema migration.

#### Log deduplication

A single recurring cause could otherwise write one line per event indefinitely.
The first occurrence of a given line inside a 60-second window is written in
full; repeats are counted, and the next line after the window carries
`(repeated N× in the previous Ms)`, so nothing is silently lost. Lines are
considered repeats only when their level, component, message **and** payload all
match — two different failures that share a message stay separate.

#### Tree-sitter parser

Structural search (`smart_outline`, `smart_search`, `learn-codebase`) shells out
to the `tree-sitter` CLI, so that executable is required for *every* language —
without it no file yields symbols, regardless of which grammars are present.

It does not arrive with the package: `tree-sitter-cli` ships JavaScript only and
downloads its executable in an install script, which keepmind suppresses along
with all other install scripts. `npx keepmind install` therefore fetches it as
its own step, and a parse that finds it missing requests it in the background
and says so rather than reporting the file as unsupported. Set
`KEEPMIND_PARSER_AUTOINSTALL=0` to suppress that fetch.

#### Tree-sitter grammars

The plugin ships grammars for the languages that appear in almost any project
(JS/TS/TSX, Python, C#, PowerShell, XML/XAML, Markdown, YAML, TOML, CSS, Bash).
Anything else is fetched on first use into `~/.keepmind/grammars`, so an install
does not carry hundreds of megabytes of grammars for languages the machine never
sees. The fetch never blocks: the file that triggered it is folded without
symbols, and the grammar is in place for the next one.

### What gets observed, and what it costs

These settings govern how much work reaches the compression model at all. They
exist because the observer's cost was measured, and almost none of it was
buying anything: the resumed observer conversation re-read its own history on
every turn (91.7% of all tokens billed), and 87.6% of the resulting records were
never retrieved again on any channel.

| Key                              | Default      | Description                                              |
|----------------------------------|--------------|----------------------------------------------------------|
| `KEEPMIND_ENABLED`               | `true`       | Master switch. `false` disables capture, session-start injection and the per-Read timeline |
| `KEEPMIND_CAPTURE_PROFILE`       | *(from mode)*| `governance`, `balanced` or `full` — see below           |
| `KEEPMIND_OBSERVER_SESSION_MODE` | `stateless`  | `stateless`: each compression is its own request. `conversational`: the legacy resumed session |
| `KEEPMIND_OBSERVE_TRIGGER`       | `batched`    | `batched`: compress during the session. `session-end`: collect everything and compress once when the turn stops |
| `KEEPMIND_OBS_FIELD_MAX_CHARS`   | `2000`       | Per-field budget for tool input/output in a prompt. Clamped to 200–16000 |

**Capture profiles.** The profile decides what is worth a model call *before* any
prompt is built, from the hook payload alone — so a skipped batch costs nothing
rather than costing a full turn to be told "nothing worth recording".

- `governance` — portfolio-level only: decisions and their rationale, migrations,
  releases, conventions, security findings, recurring problems. This is the
  memory a per-project tool cannot give you.
- `balanced` — anything that changed a file, failed, or decided something.
- `full` — anything with any signal at all (closest to pre-3.4 behaviour).

The default is derived from `KEEPMIND_MODE`: `governance` for the `code` modes
and their language overlays, `balanced` for every other mode — the governance
signals look for commits, migrations and CI config, which mean nothing in a mode
that observes something else. Setting the key explicitly always wins.

If the session-start injection feels thin after the change, `balanced` is the
step back. That injection is the part with a demonstrated payoff; it is not
worth trading for the saving.

### Session-start injection

| Key                                | Default | Description                                              |
|------------------------------------|---------|----------------------------------------------------------|
| `KEEPMIND_SESSION_START_INJECT`    | `true`  | Inject recent context when a session starts              |
| `KEEPMIND_SESSION_START_MAX_CHARS` | `4500`  | Hard ceiling, applied after rendering (~1.1k tokens)      |

The ceiling is trimmed on a line boundary and announced in the output, so a cut
never reads as "there was nothing more". Urgent hints (stale OAuth token,
degraded vector search, update notice) are added *after* the trim and are never
what gets dropped.

### Per-Read file timeline

Injected before a `Read` when earlier observations touched that file.

| Key                                | Default | Description                                              |
|------------------------------------|---------|----------------------------------------------------------|
| `KEEPMIND_FILE_CONTEXT_ENABLED`    | `true`  | Turn the per-Read injection off entirely                 |
| `KEEPMIND_FILE_CONTEXT_MIN_BYTES`  | `1500`  | Skip files smaller than this                             |
| `KEEPMIND_FILE_CONTEXT_MAX_ROWS`   | `3`     | Rows shown per file                                      |
| `KEEPMIND_FILE_CONTEXT_MIN_SCORE`  | `2`     | Specificity an observation must reach. `0` = no threshold |

Specificity scores +2 when the observation names this file as *modified*, and +2
(or +1) when it touched few files overall. At the default of `2` an observation
that merely happened to touch this file among twenty others no longer qualifies.
This hook fires on nearly every `Read`, so a weak row is not free.

### Redaction

| Key                        | Default | Description                                                    |
|----------------------------|---------|-----------------------------------------------------------------|
| `KEEPMIND_REDACT_SECRETS`  | `1`     | Emergency kill-switch. `0` disables redaction on **both** the outbound and the write path |
| `KEEPMIND_REDACT_PII`      | `1`     | `0` disables email/IPv4 masking only; credential rules stay active |

Redaction runs before a prompt leaves the machine and again before anything is
written to SQLite. See [SECURITY.md](https://github.com/ManuelStaggl/keepmind/blob/main/SECURITY.md)
for the rule set, the sensitive-file guard, and the limits.

`KEEPMIND_REDACT_PII=0` is the setting to reach for when masking hurts more than
it helps — on a machine where LAN addresses are the subject of the work rather
than something to hide.

### Memory Quality

A nested `memoryQuality` object in `settings.json`. Every field is optional.

| Key                              | Default | Description                                              |
|----------------------------------|---------|----------------------------------------------------------|
| `vectorRetention.enabled`        | `true`  | Drop vectors for projects with no activity in the window |
| `vectorRetention.inactiveDays`   | `90`    | How long a project may be dormant before eviction        |
| `expiry.enabled`                 | `false` | Archive stale, low-importance, never-recalled observations |
| `redactSecrets.enabled`          | `true`  | Credential redaction, outbound and on write              |
| `redactSecrets.pii`              | `true`  | Email and IPv4 masking (separable from the above)        |
| `redactSecrets.entropyThreshold` | `4.0`   | Bits/char before the entropy backstop masks a token      |

`vectorRetention` defaults on because it is reversible: only the vector index is
touched. The observation stays in SQLite, keyword search still finds it, and a
project that becomes active again is re-embedded automatically. `expiry`
defaults off because it archives the observations themselves.

Activity counts retrieval as well as writes, so a finished project whose
memories are still being read is not treated as dormant.

## Model Configuration

Configure which Claude model compresses your observations (only applies when `KEEPMIND_PROVIDER=claude`).

### Available Models

These are the models `npx keepmind install` offers:

| Value | Notes |
|-------|-------|
| `claude-haiku-4-5` | Recommended — fast and cheap, ideal for compression |
| `claude-sonnet-5` | Balanced quality and cost |
| `claude-opus-5` | Highest quality, most expensive |

The built-in default if you never choose one is `claude-haiku-4-5-20251001` — the
dated form of the same Haiku 4.5 model.

Compression is mechanical reformatting, not reasoning, and it runs every time you
and Claude touch a file — so the cheapest model is the right default, not a
compromise. Haiku 4.5 costs roughly a third of Sonnet 5 per token.

Older aliases stay accepted so a reinstall never rejects an existing
`settings.json`; they are simply no longer offered:
`claude-haiku-4-5-20251001` (the dated form of the current Haiku alias),
`claude-sonnet-4-6`, and `claude-opus-4-7`.

### Picking via the Installer

`npx keepmind install` prompts for the Claude model (when the Claude provider is selected) and persists the choice to `~/.keepmind/settings.json`.

### Manual Configuration

Edit `~/.keepmind/settings.json`:

```json
{
  "KEEPMIND_MODEL": "claude-haiku-4-5-20251001"
}
```

## Files and Directories

### Data Directory Structure

The data directory location depends on the environment:
- **Production (installed plugin)**: `~/.keepmind/` (always, regardless of CLAUDE_PLUGIN_ROOT)
- **Development**: Can be overridden with `KEEPMIND_DATA_DIR`

```
~/.keepmind/
├── keepmind.db           # SQLite database
├── .install-version        # Version marker written by `npx keepmind install`/`repair`
├── .vector-health.json     # Written when the vector store fails to load; cleared on success
├── settings.json           # Worker port + provider/model settings
├── grammars/               # Tree-sitter grammars fetched on demand
├── spool/                  # Hook calls buffered while no worker could accept them
├── vector-db/              # sqlite-vec store (vectors.db)
└── logs/
    ├── worker-out.log      # Worker stdout logs
    └── worker-error.log    # Worker stderr logs
```

`spool/` is normally empty. Entries appear when a hook fired while the worker was
starting, absent or overloaded — payloads that would otherwise have been dropped
— and are replayed once the worker is ready and idle. A count that never falls
means the worker is not starting; `npx keepmind doctor` reports it.

### Plugin Directory Structure

```
${CLAUDE_PLUGIN_ROOT}/
├── .claude-plugin/
│   └── plugin.json         # Plugin metadata
├── .mcp.json               # MCP server configuration
├── hooks/
│   └── hooks.json          # Hook configuration
├── scripts/                # Built executables
│   ├── version-check.js    # Sub-100ms Setup-hook version marker check
│   ├── context-hook.js     # Context injection hook
│   ├── new-hook.js         # Session creation hook
│   ├── save-hook.js        # Observation capture hook
│   ├── summary-hook.js     # Summary generation hook
│   ├── worker-service.cjs  # Worker service (CJS)
│   └── mcp-server.cjs      # MCP search server (CJS)
└── ui/
    └── viewer.html         # Web viewer UI bundle
```

## Plugin Configuration

### Hooks Configuration

Hooks are registered in `plugin/hooks/hooks.json`. The current shape uses a single dispatcher (`worker-service.cjs hook claude-code <event>`) launched through `bun-runner.js`, plus a fast Setup-phase `version-check.js`. The events wired up are:

- `Setup` → `version-check.js` (sub-100ms `.install-version` check)
- `SessionStart` → start the worker, then `hook claude-code context` (context injection)
- `UserPromptSubmit` → `hook claude-code session-init`
- `PreToolUse` (matcher `Read`) → `hook claude-code file-context`
- `PostToolUse` (matcher `*`) → `hook claude-code observation`
- `Stop` → `hook claude-code summarize`

The exact `hooks.json` entries are written by the installer; do not hand-edit them in the marketplace copy unless you know what you're doing.

### Search Configuration

keepmind provides MCP search tools for querying your project history.

**No configuration required** - MCP tools are automatically available in Claude Code sessions.

Search operations are provided via:
- **MCP Server**: 3 tools (search, timeline, get_observations) with progressive disclosure
- **HTTP API**: 10 endpoints on the worker service port (per-user, default `37700 + (uid % 100)`; see `~/.keepmind/settings.json`)
- **Auto-Invocation**: Claude recognizes natural language queries about past work

## Version Channel

keepmind supports switching between stable and beta versions via the web viewer UI.

### Accessing Version Channel

1. Open the viewer at the worker URL (default `http://127.0.0.1:<worker-port>`; the active port is the value of `KEEPMIND_WORKER_PORT` in `~/.keepmind/settings.json`)
2. Click the Settings gear icon
3. Find the **Version Channel** section

### Switching Versions

- **Try Beta**: Click "Try Beta (Endless Mode)" to switch to the beta branch with experimental features
- **Switch to Stable**: Click "Switch to Stable" to return to the production release
- **Check for Updates**: Pull the latest changes for your current branch

**Your memory data is preserved** when switching versions. Only the plugin code changes.

<Note>
Endless Mode is experimental and slower than standard mode. See [Beta Features](beta-features) for full details and important limitations.
</Note>

## Context Injection Configuration

keepmind injects past observations into each new session, giving Claude awareness of recent work. You can configure exactly what gets injected using the **Context Settings Modal**.

### Context Settings Modal

Access the settings modal from the web viewer (the worker prints its URL on startup; default is `http://127.0.0.1:<worker-port>`):

1. Click the **gear icon** in the header
2. Adjust settings in the right panel
3. See changes reflected live in the **Terminal Preview** on the left
4. Settings auto-save as you change them

The Terminal Preview shows exactly what will be injected at the start of your next Claude Code session for the selected project.

### Loading Settings

Control how many observations are injected:

| Setting | Default | Range | Description |
|---------|---------|-------|-------------|
| **Observations** | 50 | 1-200 | Total number of recent observations to include |
| **Sessions** | 10 | 1-50 | Number of recent sessions to pull observations from |

**Considerations**:
- **Higher values** = More context but slower SessionStart and more tokens used
- **Lower values** = Faster SessionStart but less historical awareness
- Default of 50 observations from 10 sessions balances context richness with performance

### Filter Settings

Control which observation types and concepts are included:

**Types** (select any combination):
- `bugfix` - Bug fixes and error resolutions
- `feature` - New functionality additions
- `refactor` - Code restructuring
- `discovery` - Learnings about how code works
- `decision` - Architectural or design decisions
- `change` - General code changes

**Concepts** (select any combination):
- `how-it-works` - System behavior explanations
- `why-it-exists` - Rationale for code/design
- `what-changed` - Change summaries
- `problem-solution` - Problem/solution pairs
- `gotcha` - Edge cases and pitfalls
- `pattern` - Recurring patterns
- `trade-off` - Design trade-offs

Use "All" or "None" buttons to quickly select/deselect all options.

### Display Settings

Control how observations appear in the context:

**Full Observations**:
| Setting | Default | Options | Description |
|---------|---------|---------|-------------|
| **Count** | 5 | 0-20 | How many observations show expanded details |
| **Field** | narrative | narrative, facts | Which field to expand |

The most recent N observations (set by Count) show their full narrative or facts. Remaining observations show only title, type, and token counts in a compact table format.

**Token Economics** (toggles):
| Setting | Default | Description |
|---------|---------|-------------|
| **Read cost** | true | Show tokens to read each observation |
| **Work investment** | true | Show tokens spent creating the observation |
| **Savings** | true | Show total tokens saved by reusing context |

Token economics help you understand the value of cached observations vs. re-reading files.

### Advanced Settings

| Setting | Default | Description |
|---------|---------|-------------|
| **Model** | sonnet | AI model for generating observations |
| **Worker Port** | `37700 + (uid % 100)` | Port for background worker service (override with `KEEPMIND_WORKER_PORT`) |
| **MCP search server** | true | Enable Model Context Protocol search tools |
| **Include last summary** | false | Add previous session's summary to context |
| **Include last message** | false | Add previous session's final message |

## Customization

Settings can be customized in `~/.keepmind/settings.json`.

### Custom Data Directory

Edit `~/.keepmind/settings.json`:
```json
{
  "KEEPMIND_DATA_DIR": "/custom/path"
}
```

### Custom Worker Port

Edit `~/.keepmind/settings.json`:
```json
{
  "KEEPMIND_WORKER_PORT": "38000"
}
```

Then restart the worker:
```bash
npm run worker:restart
```

### Custom Model

Edit `~/.keepmind/settings.json`:
```json
{
  "KEEPMIND_MODEL": "opus"
}
```

Then restart the worker:
```bash
export KEEPMIND_MODEL=opus
npm run worker:restart
```

### Custom Skip Tools

Control which tools are excluded from observations. Edit `~/.keepmind/settings.json`:
```json
{
  "KEEPMIND_SKIP_TOOLS": "ListMcpResourcesTool,SlashCommand,Skill"
}
```

**Default excluded tools:**
- `ListMcpResourcesTool`
- `SlashCommand`
- `Skill`
- `TodoWrite`
- `AskUserQuestion`

**Common customizations:**
- Include TodoWrite: Remove from skip list to track task planning
- Include AskUserQuestion: Remove to capture decision-making conversations
- Skip additional tools: Add tool names to reduce observation noise

Changes take effect on the next tool execution (no worker restart needed).

## Advanced Configuration

### Hook Timeouts

Hook timeouts are written into `plugin/hooks/hooks.json` by the installer. The current defaults match the shape of the workload at each lifecycle stage:

- Setup (`version-check.js`): 300s ceiling but normally < 100ms — only reads `.install-version`
- SessionStart (worker-start + context): 60s
- UserPromptSubmit: 60s
- PreToolUse (file-context, Read matcher): 60s
- PostToolUse (observation): 120s
- Stop (summary): 120s

The Setup hook never installs anything — runtime install (Bun, uv, `bun install`) happens in `npx keepmind install` / `npx keepmind repair` outside the session lifecycle.

### Worker Memory Limit

The worker service is managed by Bun and will automatically restart if it encounters issues. Memory usage is typically low (~100-200MB).

### Logging Verbosity

Enable debug logging:

```bash
export DEBUG=keepmind:*
npm run worker:restart
npm run worker:logs
```

## Configuration Best Practices

1. **Use defaults**: Default configuration works for most use cases
2. **Override selectively**: Only change what you need
3. **Document changes**: Keep track of custom configurations
4. **Test after changes**: Verify worker restarts successfully
5. **Monitor logs**: Check worker logs after configuration changes

## Troubleshooting Configuration

### Configuration Not Applied

1. Restart worker after changes:
   ```bash
   npm run worker:restart
   ```

2. Verify environment variables:
   ```bash
   echo $KEEPMIND_MODEL
   echo $KEEPMIND_WORKER_PORT
   ```

3. Check worker logs:
   ```bash
   npm run worker:logs
   ```

### Invalid Model Name

If you specify an invalid Claude model name, the worker logs a warning and uses the default. Valid Claude models for `KEEPMIND_MODEL`:

- `claude-haiku-4-5` (default)
- `claude-sonnet-5`
- `claude-opus-5`

Superseded aliases are still accepted: `claude-haiku-4-5-20251001`,
`claude-sonnet-4-6`, `claude-opus-4-7`.

### Port Already in Use

The default worker port is `37700 + (uid % 100)`, so different OS users on the same machine get different ports automatically. If you still hit a collision (e.g. running multiple profiles as the same UID), set a fixed port:

1. Set custom port:
   ```bash
   export KEEPMIND_WORKER_PORT=38000
   ```

2. Restart worker:
   ```bash
   npm run worker:restart
   ```

3. Verify new port:
   ```bash
   curl -s http://127.0.0.1:$KEEPMIND_WORKER_PORT/api/health | jq .port
   ```
